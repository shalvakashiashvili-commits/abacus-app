# აბაკუსი — სორობანის და ანძანის სასწავლო PWA

სუფთა HTML + CSS + JavaScript (ES მოდულები), ფრეიმვორკების, build-ის და გარე ბიბლიოთეკების (შრიფტებიც) გარეშე.
მუშაობს სრულად offline-ში, ყენდება Android-ის მთავარ ეკრანზე. ინტერფეისი და ახსნები ქართულადაა.

- აპი: `https://shalvakashiashvili-commits.github.io/abacus-app/`
- ქეშის მიმდინარე ვერსია: `abacus-v4` (`sw.js`)

## 3. მეთოდური გადაწყვეტილებები (ყველა დადასტურებულია)

### სორობანი და ფორმულები (ეტაპი 1)
1. **13 ღერო**; ერთეულის წერტილები ყოველ მესამე ღეროზე, **ყველაზე მარჯვენა (ერთეულების) ღეროდან** დაწყებული.
2. ტელეფონზე ჩანს **6 მარჯვენა ღერო** (თითო ≥ 48px), ღილაკით „13 ღერო“ — ყველა.
3. **იაპონური ორთითიანი ხერხი**: ცერა თითი მხოლოდ ქვედა მძივებს წევს ზემოთ, საჩვენებელი — დანარჩენ ყველაფერს.
4. ფორმულები **იაპონური რიგით**: `+4 = +5 −1`, `−4 = +1 −5`, `+9 = −1 +10` (ჯერ ამ ღეროზე ვაკლებ, მერე გადატანა), `−9 = −10 +1` (ჯერ სესხება), შერეული `+6 = +1 −5 +10`, `−6 = −10 +5 −1`.
5. ანგარიში მარცხნიდან მარჯვნივ (უმაღლესი თანრიგიდან).
6. **გადატანა/სესხება, რომელსაც თავად სჭირდება ფორმულა** (45 + 5, 99 + 1, 50 − 1) — დონე 4-ში.
7. გენერატორი იყენებს **მხოლოდ ნასწავლ ფორმულებს** (`allowed`); დონის ახალი ფორმულა (`focus`) ყველა მაგალითში მონაწილეობს.

### გამრავლება, გაყოფა, ათწილადები (ეტაპი 2)
8. **გამრავლება — 片落とし (kata-otoshi)**: სორობანზე იწერება მხოლოდ პირველი თანამამრავლი, ერთეულები **▼ = მარჯვნიდან მე-4 ღერო**. მარჯვენა ციფრიდან: **ჯერ ციფრს ვხსნით**, მერე მის ადგილას ვამატებთ ორნიშნა ნამრავლებს (ათეულები — იმავე ღეროზე, ყოველი შემდეგი ერთი ღეროთი მარჯვნივ).
9. **ერთეულის წესი (teii)**: გამრავლებისას პასუხის ერთეულები **▲ = ▼-დან მარჯვნივ** იმდენი ღეროთი, რამდენი (მთელი) ციფრიცაა მეორე თანამამრავლში.
10. **გაყოფა — 片落とし**: სორობანზე მხოლოდ გასაყოფი, ერთეულები **▼ = ყველაზე მარჯვენა ღერო**; განაყოფის ერთეულები **▲ = ▼-დან მარცხნივ (გამყოფის ციფრები + 1)**. განაყოფის ციფრი **2 ღეროთი მარცხნივ, თუ იყოფა**, **მეზობელ ღეროზე, თუ არ იყოფა**; ნამრავლი აკლდება ციფრის მარჯვენა ღეროდან.
11. ნაშთი იკითხება ▲-ის მარჯვნივ დარჩენილიდან (▼-ის ჩათვლით).
12. **ათწილადები**: ერთეულების ღერო — მარჯვნიდან მე-4 (წერტილიანი); გამყოფი — მძიმე (12,5). ათწილადი გამრავლებისას ▲ იწევს მეორე თანამამრავლის **მთელი ციფრების** რაოდენობით (0,3 → 0; 0,03 → −1) — ჰეფელფინგერის მიხედვით.
13. ორნიშნა გამყოფისას — **„შეაფასე და შეამოწმე“** (確商).
14. დროის ლიმიტები: 5ა ≤ 30 წმ, 5ბ ≤ 60 წმ, ტაბულა ≤ 5 წმ; გამრავლება/გაყოფა — **ლიმიტის გარეშე, მაგრამ დრო ჩანს და სტატისტიკაში იწერება**.

### ანძანი, flash anzan, გამოცდა, 修正 (ეტაპი 3)
15. 9ა ვიზუალიზაცია: სორობანი ჩანს **2,0 წმ** (მართული სავარჯიშო) / **1,5 წმ** (დავალებები, ტესტი); „მოჩვენებითი“ სორობანი — მძივები არ ჩანს, შემოწმებისას ჩნდება.
16. **Flash anzan**: მხოლოდ მიმატება; საწყისი სიჩქარე 1,5 წმ/რიცხვი; ≥ 90%-ის შემდეგ ინტერვალი **ავტომატურად −10%** (მინ. 0,3 წმ), დაბრუნების ღილაკით. ოფიციალურ კიუებს არ ასახელებს (წყაროებში სიჩქარეები განსხვავდება).
17. **„კენტეის მსგავსი“ გამოცდა**: ფორმატი (სექციები, ამოცანების რაოდენობა, ციფრები, დრო, ქულები, გამსვლელი ზღვარი) — 日本珠算連盟-ის ოფიციალური ცხრილიდან; ამოცანებს აპი ადგენს, ამიტომ **ოფიციალური გამოცდა არ არის** და ყველგან ასე იწერება.
    - დონეები: **9, 8, 7, 6 კიუს მსგავსი**; **10 კიუ არ შედის**.
    - სვეტები: 9 და 8 კიუ — მხოლოდ მიმატება; 7 და 6 კიუ — **~20% გამოკლება**.
    - დრო: **„გაზრდილი დრო (×1,5)“ — ნაგულისხმევი**, ან „ოფიციალური დრო“; ისტორიაში ჩანს, რომელი რეჟიმით გაიარე.
18. 10ბ-ის **დონის ტესტი** (20 შერეული ამოცანა) და **გამოცდა** — ცალ-ცალკე.
19. **修正 (還元 / 割り戻し)** — არასავალდებულო დონე „+“: საცდელი ციფრი მხოლოდ გამყოფის პირველი ციფრით (მაქს. 9); როცა ნამრავლი აღარ აკლდება — ციფრი −1 და ზედმეტად გამოკლებულის დაბრუნება. ასეთი ციფრი სწორზე ნაკლები არ გამოდის, ამიტომ „მცირე ციფრის“ შესწორება არ ისწავლება.

## 5. განთავსება და განახლება

**პირველი განთავსება:** GitHub → ახალი public repository `abacus-app` → ფაილები repository-ის ძირში → **Settings → Pages** → Deploy from a branch → `main` / `(root)` → Save. ყველა მისამართი ფარდობითია (`./`).

**ტელეფონზე დაყენება:** Chrome → აპის მისამართი → **⋮ → „მთავარ ეკრანზე დამატება“**. Offline-ის შემოწმება: ავიარეჟიმი → აპის დახურვა → ხელახლა გახსნა.

**ცვლილების გამოქვეყნება:**
1. ახალი ფაილი ჩაამატე `sw.js`-ის `ASSETS` სიაში (ტესტი ამოწმებს).
2. გაზარდე `CACHE_VERSION` (`abacus-v4` → `abacus-v5` …).
3. გაუშვი ტესტები → `git commit` → `git push`.
4. ტელეფონზე: აპის გახსნისას (ინტერნეტით) — „აპლიკაცია განახლდა → გადატვირთვა“, ან **პარამეტრები → განახლების შემოწმება**. პროგრესი არ იკარგება. GitHub Pages ფაილებს ~10 წუთით აქეშებს.

**პროგრესის გადატანა:** პარამეტრები → ექსპორტი (JSON) → ახალ ტელეფონზე იმპორტი.
